# マニラ給与 — 締め期間と暦月・暦年の対応

監査・税務調査で提示する前提の定義。**2026-09-13 制定。**

## 定義

| | 定義 |
|---|---|
| **締め期間** | 前月26日〜当月10日（1H）、当月11日〜当月25日（2H） |
| **給与上の月** | 1H + 2H。前月26日〜当月25日。月の名前は**支払う月**で付ける |
| **給与上の年** | その年に**支払われる**締め期間の集合。2026年＝2025-12-26〜2026-12-25 の稼働分 |
| **SSS / PhilHealth / Pag-IBIG の納付月** | 給与上の月の名前と同じ。例：8/26〜9/25 の拠出＝**9月分**として納付 |
| **BIR の課税年** | **支払った年**。RR 2-98 は「支払われた報酬（compensation paid）」に対して源泉徴収する |

## なぜこの対応になるか

BIR は**発生ではなく支払**に課税する。締め期間 12/26〜1/10 の給与は翌年1月に支払うので、
翌年の所得になる。当社の期間ラベル（`2026-01-1H` = 12/26〜1/10）は**支払月**で
付けているので、`manila_payroll_periods.year` はそのまま BIR の課税年になる。

年末調整は `year = 2026` の締め期間すべてを対象に、12月2H（12/11〜12/25）で実行する。
12/26〜12/31 の稼働分は翌年1月に支払われるため、**2027年の所得**として翌年の年末調整に入る。

社会保険は暦月単位の義務だが、締めが暦月と一致しないため、
**「給与上の月の名前＝納付月」**という対応で一貫させる。多くのフィリピン企業が
同じ方式を採っている。重要なのは**一貫していること**と、**説明できること**。

## ⚠️ 記録上の欠落（2026-09-13 時点）

上の「支払月」という前提は、**どこにも記録されていない。**
`manila_payroll_periods.paid_at` は全期間 NULL で、実際にいつ支払ったかのデータが無い。

- BIR の課税年が正しいことは、**期間ラベルが支払月に一致しているという運用の約束**に依存している
- 監査で「12/26〜1/10 の給与を本当に1月に払ったか」を問われたときの証拠が無い

**対応：** 給与を支払ったら `manila_payroll_periods.paid_at` を記録する運用にする。
過去分は銀行送金記録から遡って入れる。
