「Management Inbox のアラートが0件だが、Product Scoring では今日 TAFT に C が付いている」 という報告から調査しました。検知は正常に動いていました。止まっていたのはその先です。

報告 経理・上島 調査・修正 2026-08-27 対象 Manila / Dubai 全店

何が起きていたか

例外は検知され、タスクとして記録されていました。そのうち1件もマネージャーに届いていませんでした。

検知されたタスク 556
マネージャーへ送信 0
マネージャーの回答 3
未対応のまま 445

Manager Inbox は「BOが送信したタスク」を表示します。一度も送信されていないため、常に0件でした。 マネージャーが対応した結果0になったのではありません。

原因

① Product Score に担当者が設定されていなかった

修正済み
状況
担当の割り当ては1件だけで、4種類の例外しかカバーしていませんでした。product_score_c はどこにも含まれず、176件すべてが担当者なし。Dubai は割り当てが1件もありませんでした。
影響
BO Dashboard は担当者で絞り込むため、これらのタスクは誰の画面にも出ませんでした。
なぜ
起きたか
担当を「種類ごとに列挙する」方式だったため、列挙されなかった種類は自動的に無主になります。検知機能を追加しても、担当設定を足さなければ気付かれません。

② BOからマネージャーへの送信が一度も行われていない

運用の停止
状況
556件中、送信済み0件。送信の仕組み自体は正常に動作します（送信すると sent_at が記録される）。運用として送信操作が行われていませんでした。
影響
エスカレーション・未対応記録・Area Manager の週次スコアは、いずれも送信を起点に動きます。これらは入力ゼロのまま稼働していました。

③ 過去の「対応済み」は対応の記録ではない

把握済み
状況
閉じられている110件は、すべて closed_by = "system (historical backfill)"。移行時の一括処理で閉じられたもので、対応内容の記録はありません。
意味
「マネージャーが対応してアラートが0になったのでは」という推測に対しては、対応の記録は存在しないというのが答えです。

④ 止まっていることが、どの画面からも分からなかった

修正済み
状況
「今日は例外なし」と「全部溜まったまま」が、画面上まったく同じに見えていました。これが4か月分が誰にも気付かれなかった理由です。

対処した内容

担当設定の画面を追加（Management Channel → Owners）

HQ が「どの例外を誰が担当するか」を指定します。設定は変更するまで維持され、検知時にこの設定が使われます。

仕様内容
設定単位例外の種類 × 都市（Manila / Dubai を個別に設定）
保存時の挙動既に溜まっている未対応タスクの担当も付け替える（翌日からではなく即座に反映）
一覧に出る種類テンプレート登録済みの9種類＋実際に発生した全種類（テンプレート未登録の種別も表示）
未設定の扱い担当なしのまま。画面上部に赤で警告し、件数を明示する

担当者不在時の引き取り

BO Dashboard の各タスクに担当者名を表示し、「Take over」ボタンを追加しました。 押すと自分が担当になります。HQ の設定を書き換える必要はありません。 担当者が休みの日でも、その場で引き取って処理できます。

メニューのバッジ表示

BO Dashboard のメニューに未対応件数を表示します。開かなくても異常が分かります。

表示条件
赤バッジ重大（red）あり／2日以上放置あり／担当者なしあり のいずれか
橙バッジ未対応はあるが上記に該当しない
表示なし未対応が0件

担当者なしを「赤」に含めています。誰も見ることになっていないタスクが、3種類のうち最も危険なためです。

次にやること

1. HQ が担当を設定する

Management Channel → Owners タブで、9種類＋αの担当を指定してください。 現在は4種類・Manila のみで、Dubai は未設定です。 保存すれば、溜まっている445件にも担当が付きます。

2. BO の送信操作を運用に乗せる

これは機能の不具合ではありません。送信操作が行われないかぎり、マネージャーには何も届きません。 担当者に「タスクを確認して送信する」手順を明示的に伝える必要があります。 バッジが赤で445件と出ていても、押す人がいなければ数字は減りません。

3. 対応履歴の記録項目（未着手）

「提出写真の確認／問題の有無と分類／Discord・キッチンでのフィードバック／トレーニング実施と内容」を 記録できるようにする件は、まだ着手していません。記録用の列は既にあるため、入力画面と選択肢を定義するだけで実現できます。 ただし送信の運用が始まらないと、記録する対応そのものが発生しません。1と2の後に着手するのが順序として安全です。
