アラートが止まる理由

BO Dashboard のアラートがキッチンマネージャーに届かない件を、実データで確認しました。 17:30 に1回という案は、測ってみると足りません。その理由と代案です。

配信は壊れていません。押す人がいないだけです

Send を押すと notify_task_owner() が動き、担当マネージャーへ Discord DM が出ます。 マネージャー5名は全員 Discord 登録済みで、経路は生きています。 止まっているのは「送るものがある」と BO 担当に伝える部分だけです。

17:30 の1回では 60% しか拾えません

実装案 — A と B、どちらかを選んでください

案A（推奨）— バックアップのアラートは自動で送る

Par 割れの Send に判断は要りません。 閾値は計算済み、文面は生成済み、宛先は当番表で決まっています。 人が押すことで加わっているのは 9.9時間の遅れだけです。

  • backup 50%割れ / 70%割れ のみ、検知の 15分後に自動送信（15分は訂正の猶予）
  • 宛先は現在と同じ当番表。当番が決まっていない支店は自動送信しない（今のガードを維持）
  • 他の種類（Product Score・Disposal・Rush Check）は従来どおり人が押す。 判断が要るものと要らないものを分ける
  • MGMT_AUTOSEND_TYPES で対象を指定。やめるのは設定を空にするだけ（デプロイ不要）
  • 自動送信は sent_by='auto' で記録し、人の送信と混ざらないようにする

件数は 1.2件/日 なので、自動化しても通知が溢れません。 「決めた時間に必ず確認する」より確実で、担当の手も空きます。

案B — 人が押す運用のまま、確認を促す

ご要望どおり人を残す場合は、17:30 の1回ではなく 13:30 と 19:30 の2回にしてください。

  • その時刻に未送信があれば、当番の BO 担当へ Discord DM で件数と支店名を送る
  • 未送信が 0 件なら何も送らない（毎日鳴る通知は読まれなくなります）
  • 30分後にまだ未送信なら、もう一度だけ。それでも残れば翌朝に持ち越し、画面に日数を出す
案Bには先に片付ける前提があります

Discord に登録されているのはマネージャー5名だけで、送る側の BO 担当が入っていません。 直近30日で送信作業をしているのは Erica May Sadiasa（100件）と Aliana Manuel（89件）ですが、 2人とも未登録なので、今のままでは DM が届きません。 登録は Management Channel の設定画面から行えます。

Aliana さんの Discord 告知を止める件

先に確認したいこと

OS のアラートは「支店ごと・品目ごとに、その支店のマネージャーへ個別に」送られます。 Aliana さんの告知が全店まとめた一覧だとすると、止めた瞬間に 「全体でどこが薄いか」を見る人がいなくなります。個別DMは受け取った本人しか見ません。

止める前に、告知の実物を1回見せていただけますか。 同じ内容を OS 側から1本の要約として出す必要があるなら、それも一緒に作ります （2回の確認時刻に合わせて「本日のPar割れ一覧」を1本投稿する形）。
