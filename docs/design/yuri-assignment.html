検証で見つけた本命

承認段階は発注時に決まり、後から明細を編集しても再ルーティングされません。 つまり分割しなくても承認マトリクスは抜けられます — ラインの下で出して、後で増やすだけ。 閾値際のアラート11件のうち4件が検知後に金額を編集されており、 1件は ₱19,855（99.3%）から ₱22,625（ライン超え）に動いていました。 これを検知する APPROVAL_LEVEL_BELOW_AMOUNT を新設しました。

閾値 ₱20,000 は発明していません。 生きている承認マトリクスの level1 上限（MANAGER→HR_MANAGER の壁）を読んでいるので、 Approval Matrix 画面で変えれば検知も動きます。

実際に探したら、分割発注は1件もありませんでした。 同日の複数発注15件のうち10件は店舗別の通常発注（TAFT/PAR/CUBに1本ずつ）、 残る5件は0.2〜2.4分間隔の二重送信。実在した問題は分割ではなく重複だったので、 そちらを検知するルールを足しました。
