PHASE 1 見えるようにする 1〜2日

ツール3本。ここが土台です。

① run_sql — 読み取り専用の任意SQL

16ツールの制限を外します。安全側の条件は必須です。

  • 読み取り専用ロールで接続（`GRANT SELECT` のみ）。アプリのロールを使い回さない
  • SET LOCAL statement_timeout = 20s ＋ 常に ROLLBACK
  • 返却は最大1,000行。超えたら「N行中1,000行」と明示
  • 画像列を強制除外 — photo_data / invoice_photo_b64 / image_data 等。1列で864MBあり、過去に本番を3回落としています

② describe_schema — 表・列・行数・最終更新日

最終更新日が要点です。これがあれば actual_attendance を見た瞬間に 「7/9で止まっている」と分かります。

③ すべての結果に鮮度を添える

{ "rows": [...],
  "source": "actual_attendance",
  "last_updated": "2026-07-09",
  "stale": true,
  "warning": "この表は56日間更新されていません" }

既存の16ツールにも同じものを付けます。 今日いちばん危険なのは新しいツールではなく、古いツールが黙って古い答えを返すことです。

PHASE 2 数字の意味を読めるようにする 2〜3日

ここが一番差が出ます。今回のセッションの発見は、大半がデータではなくコードから出ています。

発見出所データだけだとどう読むか

 いずれもデータだけ見ると逆の結論になります。

④ search_code — リポジトリ全文検索

Herokuのdynoにはバックエンドしか無いので、両リポジトリを索引テーブルに入れます （ファイル名・行番号・本文）。デプロイ時か日次で更新。 「この列はどこで書かれるか」「この判定はどう計算されるか」が引けるようになります。

⑤ 落とし穴ノートを引けるようにする

CLAUDE.md には80項目の教訓が既にあります。 これを表に入れ、触れた表名・列名で引けるようにします。 

gps_ok        → false は「圏外」とは限らない。精度を確認すること
container     → 容器数ではなく容器に対する%（0-100）
prep_time     → excluded_reason 付きは集計に入らない
backup par    → closing レポートのみ判定対象
payroll       → 過去期間の再計算は現レートで上書きされる

この2本が入ると、「データを読む」から「データの意味が分かる」に変わります。

PHASE 3 深く掘れるようにする 半日
  • ラウンド数 8 → 30。今回の店舗評価の検証は クエリ12回かかっています。8回では途中で終わります
  • モデルを Sonnet から Opus へ（AI_ANALYTICS_PRO_MODEL で変更可・デプロイ不要）。 仮説を立てて否定しにいく作業で差が出ます
  • タイムアウトを 300秒 → 900秒

設定変更が中心で、工数はほぼかかりません。

PHASE 4 間違いを自分で見つけさせる 1日

結論を出す前に、それを否定する材料を探させる手順をシステムプロンプトに入れます。

  • 対照群を必ず取る。「彼は385m離れている」→ 同じ拠点の他スタッフは12〜32mと比べて初めて意味が出ます
  • 件数の異常を疑う。全件同じ値・同一秒に1,227件・毎日ぴったり385m — これらはデータではなく仕組みの兆候です
  • 答えられないときは答えない。 「9月の3日間で13操作」から勤務実態は判定できません。 「区別できない」と言えることが精度です
実際に起きた例

私は昨日、あるスタッフを「圏外打刻の最も明確な例」と名指しで誤って報告しました。 データだけを見た結果です。CCTVの証言とコードを突き合わせて初めて、 不正ではなく端末の測位不良だと分かりました。 この工程が無いと、同じ間違いを自動で量産します。

それでも残る差

ここまでやっても、DBにもコードにも無い情報は渡せません。今回の例で言えば:

  • 「ドバイはまだ運用前」— どこにも書かれていません
  • 「CCTVで本人がキッチンにいた」— OSの外の事実です
  • 「Base Roll 5 と 8 は別商品」— 厨房の知識です
  • 「山田さんはBOマネージャー」— staff_master.position は空欄でした

これらは人が伝えるしかありません。 ただし、伝えられた前提を教訓ノートに書き足していけば、次からは知っている状態になります。 CLAUDE.md の80項目が、まさにその蓄積です。
