How to record a physical count

After counting actual stock in the store, store staff enter the quantities in the OS. This becomes the "Actual Inventory" baseline.

  • 1Go to Admin → Inventory → Full Inventory Count
  • 2Select City, Branch, Date, and Cycle (15th or Month-end)
  • 3Select a Count Template from the dropdown to pre-load items
  • 4Enter counted quantities for each ingredient/product
  • 5Click Submit Count to finalize
ℹ️ Count Templates define which items appear in the count sheet. Set them up under Count Templates tab first.

棚卸しデータの入力方法

店舗で実際に在庫を数えた後、店舗スタッフがOSに数量を入力します。これが「実際在庫」のベースラインになります。

  • 1Admin → Inventory → Full Inventory Count に移動
  • 2City（都市）、Branch（店舗）、Date（日付）、Cycle（15日 または 月末）を選択
  • 3ドロップダウンから Count Template を選択してアイテムリストを読み込む
  • 4各食材・商品の数えた数量を入力
  • 5Submit Count をクリックして確定
ℹ️ Count Template で棚卸しシートに表示するアイテムを定義します。まず Count Templates タブで設定してください。

POS Sales → Ingredient Deduction Automatic via UrbanPiper sync POS販売 → 食材自動減算 UrbanPiper 同期による自動処理

How ingredient deduction works

Every time a menu item is sold via POS (UrbanPiper), the OS automatically deducts the required ingredients from theoretical stock based on the Cost Calculation BOM.

  • 1POS sale syncs via UrbanPiper → inv_pos_menu_sales_daily
  • 2System looks up BOM in Cost Calculation (menu_item_master)
  • 3Leaf ingredients are resolved and deducted from the ledger
  • 4View in Inventory → POS Sync tab
⚠️ Important: If a menu item is NOT registered in Cost Calculation, it will NOT deduct ingredients. This creates a gap.

To check registrations: Admin → Cost Calculation

食材自動減算の仕組み

POSでメニューアイテムが販売されるたびに（UrbanPiper経由）、OSはCost Calculation の BOMに基づいて理論在庫から必要な食材を自動的に減算します。

  • 1POS販売データが UrbanPiper 経由で同期 → inv_pos_menu_sales_daily
  • 2システムが Cost Calculation（menu_item_master）のBOMを参照
  • 3末端食材が解決されて台帳から減算
  • 4Inventory → POS Sync タブで確認
⚠️ 重要: メニューアイテムが Cost Calculation に登録されていない場合、食材は減算されません。これがギャップの原因になります。

登録確認: Admin → Cost Calculation

Record Disposals & Staff Meals Admin → Disposal Report New Feature 廃棄・賄い飯を記録する Admin → Disposal Report 新機能

Submit a Disposal Report at end of day

Any ingredient or prepared item that is thrown away (end-of-day leftover, spoilage) or used as a staff meal must be recorded. These are now automatically deducted from the inventory ledger.

  • 1Go to Disposal Report in the side menu
  • 2Select City, Branch, Date, and Shift
  • 3Under "Disposal Items", search and add each item with quantity and disposal reason:
    • EOD Leftover (end-of-day)  • Spoilage  • Staff Meal  • Other
  • 4Click Submit Disposal Report
✅ After submitting, the system automatically posts entries to the inventory ledger. Menu items are expanded via BOM — all ingredients are deducted correctly.

当日終了時に廃棄報告書を提出する

廃棄された食材や調理品（日次残余、傷み）、または賄い飯として使用されたものはすべて記録が必要です。これらは在庫台帳から自動的に減算されます。

  • 1サイドメニューの Disposal Report に移動
  • 2City、Branch、Date、Shift を選択
  • 3「Disposal Items」で各アイテムを検索・追加し、数量と 廃棄理由 を入力:
    • EOD Leftover（日次残余） • Spoilage（傷み） • Staff Meal（賄い） • Other
  • 4Submit Disposal Report をクリック
✅ 提出後、システムが在庫台帳に自動投稿します。メニューアイテムはBOMで展開され、すべての食材が正しく減算されます。

Retroactive Sync (Past Reports)

Disposal reports submitted before this feature was activated are not yet in the ledger. Use the "Sync to Ledger" button on each past report in the Past Reports section to backfill them. This is idempotent — safe to run multiple times.

⚠️ Action required: For all disposal reports before 2026-08-16, click "Sync to Ledger" on the Disposal Report page (Past Reports section). Filter the date range to find older reports.

過去レポートの遡及同期

この機能が導入される前に提出された廃棄レポートはまだ台帳に反映されていません。過去レポートセクションの各レポートにある 「Sync to Ledger」 ボタンを使って遡及入力してください。べき等性があり、複数回実行しても安全です。

⚠️ 要対応: 2026年8月16日以前のすべての廃棄レポートについて、Disposal Report ページ（Past Reports セクション）の 「Sync to Ledger」 ボタンをクリックしてください。日付範囲を絞り込んで古いレポートを表示できます。
4

View Inventory Gap in Ledger Admin → Inventory → Ledger 台帳でギャップを確認する Admin → Inventory → Ledger

Reading the Ledger / Balances page

The Ledger shows the theoretical stock on-hand calculated from all movements (deliveries, POS consumption, disposals). Compare this against your physical count to find the gap.

  • 1Go to Admin → Inventory → Ledger tab
  • 2Select City and Branch (or "All branches")
  • 3Set a date range and review QTY ON HAND
  • 4Negative values = theoretical stock went below zero
  • 5Compare with last physical count → calculate gap
🔴 Negative QTY ON HAND means consumption is higher than recorded deliveries. This could indicate unrecorded deliveries, unregistered POS items, or theft.

台帳/残高ページの見方

台帳はすべての動き（仕入れ、POS消費、廃棄）から計算された理論的な手持ち在庫を表示します。これを実際の棚卸し結果と比較してギャップを見つけます。

  • 1Admin → Inventory → Ledger タブに移動
  • 2City と Branch を選択（または「All branches」）
  • 3日付範囲を設定して QTY ON HAND（手持ち数量）を確認
  • 4マイナス値 = 理論在庫がゼロを下回った状態
  • 5最新の棚卸し結果と比較 → ギャップを計算
🔴 QTY ON HAND がマイナス = 消費量が記録された入荷量を超えています。未記録の仕入れ、未登録のPOSアイテム、または盗難の可能性があります。

Gap Analysis — Example Theoretical vs Actual comparison ギャップ分析 — 例 理論在庫 vs 実際在庫の比較

After running a physical count, compare it with the theoretical stock from the ledger. A negative gap (theoretical < actual) means more stock on hand than expected — possible unrecorded consumption. A positive gap (theoretical > actual) means stock is missing.

棚卸し実施後、台帳の理論在庫と比較します。マイナスギャップ（理論 < 実際）= 予想より多い在庫 → 未記録消費の可能性。プラスギャップ（理論 > 実際）= 在庫が不足 → 調査が必要。

Business Improvement — Root Cause Analysis Fix the gap for good 業務改善 — 根本原因分析 ギャップを根本から解消する

A persistent inventory gap almost always has one of these root causes. Identify which applies and take the corrective action.

在庫ギャップが続く場合、ほぼ必ずこのいずれかが原因です。該当するものを特定して是正措置を取ります。

📋
Missing Cost Calculation BOMCost Calculation BOM 未登録

A menu item sold via POS has no BOM in Cost Calculation → zero ingredients deducted → ledger never decrements. Fix: register all menu items in Admin → Cost Calculation.POSで販売されるメニューアイテムのBOMがCost Calculationに未登録 → 食材が減算されない → 台帳が減少しない。対応: Admin → Cost Calculation でメニューアイテムを登録。

🗑️
Unrecorded Disposal廃棄の未記録

Staff discarded food without filing a Disposal Report → ledger does not deduct → gap grows. Fix: enforce daily closing disposal report submission for every branch.廃棄報告書なしに食材を廃棄 → 台帳から減算されない → ギャップが拡大。対応: 全店舗でクローズ時の廃棄報告書提出を義務化。

🍱
Unrecorded Staff Meals賄い飯の未記録

Staff meals consumed but not logged in the disposal report as "Staff Meal" reason → unaccounted consumption. Fix: add staff meals to each closing disposal report.賄い飯が廃棄報告書の "Staff Meal" 理由として記録されていない → 未計上の消費。対応: クローズ時の廃棄報告書に賄い飯を必ず追記。

📦
Missing Delivery Records入荷記録の漏れ

Deliveries received but not entered in Daily Inventory Input → ledger never credits the incoming stock. Fix: ensure all supplier/CK/warehouse deliveries are recorded on the day they arrive.仕入れを受け取ったがDaily Inventory Inputに入力されていない → 台帳に在庫が加算されない。対応: 全ての仕入れ（サプライヤー/CK/倉庫）は受け取り当日に記録。

⚖️
Portioning Varianceポーション差異

Actual portion sizes differ from the BOM specification → more or less ingredient used per dish than expected. Fix: regular portioning audits and BOM spec updates.実際のポーションサイズがBOM仕様と異なる → 1皿あたりの使用量が期待値とずれる。対応: 定期的なポーション監査とBOM仕様の更新。

🔍
Theft / Shrinkage盗難・ロス

If all other causes are ruled out and a large gap persists, consider internal shrinkage. Escalate to management for investigation. Cross-check with CCTV records.他の原因を排除してもギャップが続く場合、内部ロスを検討。管理者にエスカレートして調査。CCTVと照合。
