Price Monitor — Session Renewal Manual

各プラットフォームのセッションが切れたときの再設定手順。

● Careem Partners ● Noon Food RMS ● Keeta Merchant Portal ● Grab Food PH ● Talabat Partner Portal 4時間ごと自動チェック
🔔

いつ再設定が必要か

Discord DMに SESSION_EXPIRED の通知が届いたとき。
Careemは数週間〜1ヶ月、Noonは数週間〜数ヶ月、Keetaは約30日、Grab Foodは約30日、Talabatはセッションクッキーが数週間〜数ヶ月で切れる（JWTは4時間ごとに自動更新されるため手動対応不要）。
通知が届かなければ何もしなくてよい。

Talabat AE
partner-app.talabat.com — Dubai 14店舗（Sushi ZEN / Ramen ZEN）
Talabatの仕組み： Bearer JWT（4時間有効）は毎回の自動実行時に refresh-token.js が無人でリフレッシュする。セッション更新が必要になるのは、JWTの基になっているセッションクッキーが切れたとき（数週間〜数ヶ月）だけ。
1
プロジェクトフォルダへ移動
cd /Users/jaynishimura/Desktop/sushizen-shift-pwa
2
セットアップスクリプトを実行
node scripts/talabat/setup-session.js
Chromiumブラウザが自動で開く。
3
ブラウザでTalabatにログイン
partner-app.talabat.com が開く。メールアドレスとパスワードを入力。
4
2FAが表示されたら完了させる
スマートフォンのOTPまたはメールOTPを入力。その後ダッシュボードへ自動遷移する。
2FAページ（/2fa）での60秒は消費される — 慌てず確実に入力すること。
5
60秒以内にMenu Managementへ移動
ダッシュボード表示後、左サイドバーの Menu Management をクリック。ターミナルにAPIキャプチャログが流れたら成功（「Captured vendor API call」など）。
6
セッションをトリム（軽量化）する
node scripts/talabat/trim-session.js
Bearer tokenを抽出してb64ファイルを生成。65,536バイト以内に収まっていることを確認（「✅ Fits!」と表示される）。
7
GitHub Secretを更新してテスト
cat scripts/talabat/talabat-session.b64.txt | gh secret set TALABAT_SESSION_STATE gh workflow run talabat-price-check.yml
ワークフローが成功し、全14ベンダーで priced items が表示されれば完了。
!
セッションファイルをgitに入れない
talabat-session.json / talabat-session.b64.txt / talabat-api-discovery.json は .gitignore 済み。git status で確認してからpushすること。
Step 2 — GitHub Secretを更新する
🔑

GitHub Actions Secret の更新

1
GitHubリポジトリのSettings を開く
freestyler2026/sushizen-shift-pwa › Settings › Secrets and variables › Actions
2
該当するSecretの「Update」をクリック
CAREEM_SESSION_STATE
← Careemを更新したとき
NOON_SESSION_STATE
← Noonを更新したとき
KEETA_SESSION_STATE
← Keetaを更新したとき
GRAB_SESSION_STATE
← Grab Foodを更新したとき
TALABAT_SESSION_STATE
← Talabatを更新したとき
3
コピーした値をペーストして保存
Value フィールドに Step 1 でコピーした b64 文字列をペーストして Update secret をクリック。
Talabatはコマンドラインから直接更新可能: cat scripts/talabat/talabat-session.b64.txt | gh secret set TALABAT_SESSION_STATE
Step 3 — 動作確認

🧪 手動で実行して確認する

● Careem

GitHub Actions → Careem Price Check → Run workflow をクリック。緑のチェックが出れば成功。

● Noon

GitHub Actions → Noon Food Price Check → Run workflow をクリック。緑のチェックが出れば成功。

● Keeta

GitHub Actions → Keeta Price Check → Run workflow をクリック。緑のチェックが出れば成功。

● Grab Food PH

GitHub Actions → Grab PH Price Check → Run workflow をクリック。成功すると3店舗 × 89アイテムを確認。

● Talabat AE

GitHub Actions → Talabat AE Price Check → Run workflow をクリック。ログで全14ベンダーの「priced items」が表示されれば成功。
コマンドラインで確認する場合:

gh run view $(gh run list --workflow=talabat-price-check.yml --limit 1 --json databaseId -q '.[0].databaseId') --log 2>&1 | grep -E "Vendor [0-9]+|priced items|expired" | head -30

「Session expired」が出た場合は Step 1 のTalabat手順を再実施。「Token still valid for Xh」が表示されれば自動リフレッシュは正常動作中。

失敗した場合は、Step 1 から再実施。ログイン後にダッシュボードが完全に表示されてから Enter を押すこと（Talabatはその後にMenu Managementへ移動）。
注意： パスワードは自分で入力すること。スクリプトや Claude に入力させないこと。
Careemのcron: 毎時00分（1,5,9,13,17,21 UTC）／ Noonのcron: 毎時30分（1,5,9,13,17,21 UTC）／ Keetaのcron: 毎時00分（2,6,10,14,18,22 UTC）／ Grab Foodのcron: 毎時00分（3,7,11,15,19,23 UTC）／ Talabatのcron: 毎時30分（1,5,9,13,17,21 UTC）
セッションファイル: scripts/careem/careem-session.json / scripts/noon/noon-session.json / scripts/keeta/keeta-session.json / scripts/grab/paranaque-session.json / scripts/talabat/talabat-session.json（Gitには含めないこと）
セッション有効期限: Keeta・Grab Foodは約30日 / Talabatのクッキーは数週間〜数ヶ月（JWTは4時間ごと自動更新）。期限切れ通知が届いたら上記手順で更新すること。
