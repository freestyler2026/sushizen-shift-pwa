🏪 ストアマネージャーの方へ🏪 For Store Managers
このシステムでマネージャーがすることは1つだけです。
Back Office（BO）から届いた指示を Manager Inbox で確認し、ボタンを選んでタップする。それだけです。
文章を書く必要はありません。電話もメッセージも不要です。
There is one thing this system asks of you as a manager.
Open Manager Inbox, read the instruction from Back Office, and tap one button to respond. That's it.
No writing. No calls. No messages to anyone.

① Manager Inboxを開く① Opening Manager Inbox

アクセス方法How to access
  1. 1
    上部NavBar → 「Management Inbox」をタップ
    Tap "Management Inbox" in the top NavBar
    見当たらない場合はログインしているアカウントのロールを確認してください（MANILA_MANAGEMENT / DUBAI_MANAGEMENT / HQ が必要）。
    If you don't see it, check your login role (MANILA_MANAGEMENT / DUBAI_MANAGEMENT / HQ required).
  2. 2
    自分の支店タブを選択
    Select your branch tab
    画面上部に支店ボタン（PAR / CUB / TAFT など）が並んでいます。担当支店を選ぶとその支店のタスクのみ表示されます。
    Branch buttons (PAR / CUB / TAFT etc.) appear at the top. Select your branch to see only that branch's tasks.
  3. 3
    「Pending」件数を確認
    Check the "Pending" count
    赤い数字が「今すぐ対応が必要なタスク数」です。0なら今日はすることがありません。
    The red number = tasks requiring your action now. 0 means nothing to do today.
⏰ いつ確認すればいい？ Back OfficeからInboxに指示が届いたときです。🔴タスクは届いてから90分以内、🟠タスクは4時間以内に返答してください。連絡を受けたらすぐに開いて確認するのが理想です。 When should I check? When Back Office sends an instruction to your inbox. Respond to 🔴 tasks within 90 minutes, 🟠 tasks within 4 hours. Ideally, open it as soon as you're notified.

② 指示が届いたら：返答の手順② When an instruction arrives: How to respond

  1. 1
    🔴 または 🟠 のカードを見つける
    Find the 🔴 or 🟠 card
    「Action Required」バッジが付いたカードが未対応タスクです。🔴が上に表示されます（より緊急）。
    Cards with "Action Required" badge are pending tasks. 🔴 appears above 🟠 (higher urgency).
  2. 2
    指示文を読む（イタリック体の文章）
    Read the instruction text (shown in italics)
    何をすべきかが具体的に書かれています。「今すぐ〇〇してください」「確認してください」など。
    Tells you exactly what to do — "submit now", "confirm with staff", etc.
  3. 3
    実際に対応する
    Take the action
    まずシステム上または現場で指示の内容を実行してください。返答ボタンを押すのは実行した後です。
    First actually do what the instruction says — in the system or on the floor. Tap the response button after you act.
  4. 4
    ボタンを1つ選んでタップ → 完了
    Tap one button → Done
    タップした瞬間に送信されます。確認ポップアップが出たら「Confirm」を押すとカードが消えて返答完了です。
    Sends immediately on tap. If a confirmation popup appears, press "Confirm" — the card disappears and you're done.

Appears once you have selected the cause. This records what you did, not what happened. Two stores with the same cause but different actions get different outcomes — BO reads this field to judge how the store responded.

Feedback given only in the kitchen reaches whoever was standing there. Posted to Discord, the whole team can read the same point and refer back to it, and repeats become visible. If you had to say it on the floor first, post a line to Discord afterwards and tick both.

選んだチャンネルは、返答後のカードと BO Dashboard の両方に Discord / Kitchen のバッジとして表示されます。

The channel you pick shows as a Discord / Kitchen badge on your answered card and on the BO Dashboard.

写真が複数枚あるアラート：1枚ずつ回答しますAlerts covering several photos: answer them one at a time

製品スコアのアラートは、その日その店舗でC以下だった写真をまとめて1通で届きます。通知が1日に何通も来ないようにするためです。ただし回答は写真ごとに分かれています — 13:30・13:40・14:49 の3枚は別々の出来事であることがほとんどなので、それぞれに Issue と Action とフィードバック先を選びます。

A product-score alert arrives as one message covering every photo that scored C or below at your branch that day — that is what keeps the notifications down. But the answers are per photo: three photos at 13:30, 13:40 and 14:49 are usually three separate events, so each one gets its own Issue, Action and feedback channel.

  • 写真ごとに撮影時刻・グレード・スコア・投稿者と写真そのものが表示されます。
  • 上部に 「1 / 3 done」 のカウンターが出ます。
  • 全部の写真に回答するまでタスクは完了しません。途中で閉じても、回答済みの写真はそのまま残ります。
  • Each photo shows its time, grade, score, who posted it — and the picture itself.
  • A "1 / 3 done" counter sits at the top.
  • The task is not finished until every photo has an answer. You can leave and come back; answers already given are kept.

⑤ タスクメッセージスレッド⑤ Task Messages Thread

スレッドとは？What is the thread?

各タスクに紐づいた双方向のメッセージ欄です。BOスタッフが先にメッセージを送ってくることが多いため、「● New from BO」インジケーターが表示されたら内容を確認して返信してください。Discord/LINEなど社外ツールへの連絡は不要になります。

A bidirectional message thread attached to each task. Back Office staff often initiates first — to follow up on pending tasks, ask questions, or request confirmation. When you see the ● New from BO indicator, open the thread and reply. No Discord or LINE needed.

  1. 1
    タスクカードの「Messages」ボタンに「● New from BO」が表示されたらタップ
    When "● New from BO" appears on the Messages button — tap to open
    PendingタスクにもCompletedタスクにも表示されます。BOからの質問・フォローアップが届いています。
    Appears on both pending and completed tasks. BO has sent a follow-up or question that needs your attention.
  2. 2
    内容を確認し「Reply to Back Office…」欄で返信
    Read the message and reply in the "Reply to Back Office…" field
    Enterキー、またはSendボタン（→アイコン）で送信。あなたのメッセージは琥珀色「You」バッジで表示されます。
    Press Enter or click the Send button (→ icon). Your messages appear with an amber "You" badge.
  3. 3
    自分からメッセージを送ることも可能
    You can also send the first message yourself
    「● New from BO」がなくても、Messagesボタンをタップすれば入力欄が開きます。補足や進捗報告を能動的に送ることができます。
    Even without the indicator, tap Messages to open the input field. You can proactively send updates or add context.
💡 実際の使われ方：BOスタッフが「まだ回答がありませんがどうなっていますか？」「その後あの問題はどうなりましたか？」のようなフォローアップを送ってくることが多いです。インジケーターが表示されたら優先的に確認してください。スレッドへの参加は任意ですが、返信することで問題の解決が早まります。 How it's typically used: BO staff often sends messages like "Still waiting — any update?" or "How did that issue turn out?" when a task has no response or needs follow-up. When the ● New from BO indicator appears, check it promptly. Replying is optional but speeds up resolution.

⑥ よくある質問・困ったとき⑥ FAQ & Troubleshooting

❓ タスクが表示されない / Pending: 0 になっているNo tasks showing / Pending: 0
正常です。 Pending 0 は「今日はBOからの指示がない、または全て対応済み」ということです。

それでも「来たはずなのに見当たらない」場合：
1. 支店タブが正しいか確認してください（PAR / CUB / TAFT）
2. ページを手動でリロードしてください（ページを閉じて再度開く）
3. 「Show Done」トグルをONにすると返答済みタスクも表示されます This is normal. Pending 0 means "no BO instructions today, or all tasks already handled."

If you expected a task but don't see it:
1. Check you've selected the correct branch tab (PAR / CUB / TAFT)
2. Manually reload the page (close and reopen)
3. Turn on "Show Done" toggle to see already-responded tasks
❓ 間違ったボタンを押してしまったI tapped the wrong response button
返答は送信後に自分で取り消すことはできません。BOスタッフに直接連絡して、状況を説明してください。BOスタッフ側でタスクの状態を確認・調整できます。 Responses cannot be undone by yourself after submission. Contact your BO staff directly and explain what happened. The BO staff can check and adjust the task status on their end.

例：「Power outage — POS down」「No staff with training for this」「Supplier not yet arrived」

詳しく書く必要はありません。BOスタッフが内容を確認した上でフォローします。 One sentence is enough.
Examples: "Power outage — POS down" / "No staff with training for this" / "Supplier not yet arrived"

No need for a detailed explanation. BO staff will review and follow up.

In a future update (Week 7), unanswered tasks will auto-escalate and notify the Area Manager. Missed responses will also be reflected in the weekly compliance score.

なぜこのシステムが必要かWhy This System Exists

背景Background
  • 問題1 — 例外の見落とし：PMバックアップレポートが未提出でも、BOスタッフが手動でチェックしなければ気づかない。
  • 問題2 — 指示の曖昧さ：「対応して」と言われても、マネージャーが何をすべきか分からない。
  • 問題3 — フォローアップなし：指示を出しても返答確認が徹底されない。
  • Problem 1 — Missed exceptions: If the PM Backup Report is not submitted, nobody notices unless BO staff manually checks.
  • Problem 2 — Vague instructions: Telling a manager to "handle it" doesn't tell them what to do.
  • Problem 3 — No follow-up: Instructions get sent but responses are never confirmed.
このシステムの解決策How This System Solves It
  • 自動検知：OSが例外を自動的に見つけ、重要度を判定（🔴 緊急 / 🟠 注意）。
  • 事前作成テンプレート：Back Officeスタッフは指示文を作成せず、ボタン1つで送るだけ。判断は不要。
  • 選択式返答：マネージャーは[完了] / [できない — 理由] から選ぶだけ。文章を書く必要なし。
  • 完全ログ：誰が何を、いつ送り、いつ返答したか全て記録。
  • Auto-detection: OS finds exceptions automatically and classifies severity (🔴 Critical / 🟠 Caution).
  • Pre-written templates: Back Office staff don't write instructions — they just choose and click. No judgment needed.
  • Selection-only response: Managers select [Done] / [Cannot — Reason]. No writing needed.
  • Full audit log: Who sent what, when, and when it was responded to — all recorded.
💡 このシステムの対象はフィリピン・マニラ店舗です。マネージャーの判断能力に依存せず、システムが正しい行動を定義します。 This system targets Manila, Philippines stores. Rather than depending on a manager's judgment, the system defines the correct action.

重複排除ロジックDeduplication Logic

  • source_id：各タスクに例外の発生源IDを記録（製品スコア行のDB ID、スタッフ名、支店コード等）。
  • 重複チェック：同じ source_id で status=open または status=sent のタスクが存在する場合、新規タスクを作成しない。
  • 結果：同じ日に複数回 Run Detection を実行しても、新規例外のみ追加される。「0件」は全例外が処理済みの正常状態。
  • source_id: Each task records the origin ID of the exception (product scoring row DB ID, staff name, branch code, etc.).
  • Dedup check: If a task with the same source_id and status=open or status=sent already exists, no new task is created.
  • Result: Running detection multiple times on the same day only adds genuinely new exceptions. "0 created" means all current exceptions already have open tasks — this is normal.

/admin/management/par-levels

The thresholds the 70% / 50% backup alerts compare against. If this number is wrong, the alert is wrong.
⚠️ 初期値は「提案値」であって目標値ではありません。「Propose from last 30 days」は直近30日の提出実績の中央値を入れます。中央値は「その支店が普段どれだけ持っているか」であって「どれだけ持つべきか」ではありません。PROPOSED（黄）の行は誰もレビューしていない状態で、レビュー前でもアラートは発火します。数字を修正すると REVIEWED（緑）に変わります。 The initial numbers are proposals, not targets. “Propose from last 30 days” fills in the median of what was actually submitted. A median says what the branch typically holds, not what it should hold. Rows marked PROPOSED (amber) have not been reviewed by anyone, and alerts still fire on them. Editing the number marks it REVIEWED (green).
単位の扱いHow units are handled

同じアイテムが日によって 500 g と 1 kg の両方で記録される実例があります。そのまま合計すると 501 になってしまうため、システムは比較前に g→kg / ml→l / pc→pcs へ換算し、1日分を合算してからパーレベルと比較します。換算しても単位が混在するアイテム、およびパーレベルの単位と当日の単位が食い違うアイテムは判定せず「スキップ」として報告されます — 判定していないものが「問題なし」に見えるのが一番危険だからです。

The same item is genuinely recorded as both 500 g and 1 kg on different days; summing those raw gives 501. Quantities are therefore converted (g→kg, ml→l, pc→pcs) and summed per day before being compared. An item still mixing units after conversion — or whose par unit disagrees with the day's reading — is not judged, and is reported as skipped. An unjudged item reading as a passing one is the failure mode worth avoiding.

    Existing values are left alone — a manual correction outranks the history it came from.
  2. 2
    PROPOSED の行を上から確認して実際の目標値に直す
    Work down the PROPOSED rows and correct each to the real target
