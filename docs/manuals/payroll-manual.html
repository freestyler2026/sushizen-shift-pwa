Payroll System Overview
Admin → Payroll
Two independent engines — Manila (PHP, semi-monthly, statutory deductions) and Dubai (AED, monthly, auto-adjustment) — sharing loans, inquiries, and My Pay.

Mid-Period Hire & Resignation Handling

When hire or resign falls mid-period, payroll automatically pro-rates:

  • New hire — set hire_date. Engine pays from hire_date → period end. Pre-employment days auto-set to rest (no deductions).
  • Resignation — set last_working_date. Engine pays period start → last_working_date. Post-resignation days auto-set to rest (no deductions).
  • The system auto-syncs last_working_date from HR Separation records if not set manually.
  • Both conditions can combine in one period (early hire + early resign).

⚠️ After setting, run Compute All. Staff with this field show an amber "Last day" badge in the table.

💡 Use Auto-match to link profiles to Bayzat employee IDs — enables automatic matching during DTR sync.

Government Tables
/admin/payroll/manila/gov-tables
Configure statutory contribution tables. Update whenever government issues new rates.
SSS

Lookup by Monthly Salary Credit (MSC). Rows: comp range, MSC, EE/ER/EC amounts. WISP when MSC > ₱20,000.

EE share (deducted from staff) ER share (employer cost) EC WISP (MSC > ₱20,000)

Upload via Gov Tables → SSS tab → Upload CSV (columns: compensation_from/to, msc, ee/er/ec_amount, wisp_ee/er, effective_date)

PhilHealth

Rate % with min/max. Currently 5% total (EE+ER 2.5% each), clamped ₱10k–₱100k basic.

Base for calculation
base = monthly_basic_rate (NOT gross — OT excluded)
Pag-IBIG / HDMF

EE: 1% if basic ≤ ₱1,500, else 2%. ER: always 2%. Base capped at ₱10,000.

Typical result
EE ₱200 + ER ₱200 = ₱400/month
BIR / TRAIN Law (Withholding Tax)

Annual bracket table. Engine annualizes taxable income → lookup bracket → annual tax ÷ 12 = monthly WHT.

WHT Calculation Steps
1. taxable_monthly = gross_monthly − (EE_SSS + EE_PH + EE_PI) − de_minimis_exempt
2. annual_taxable = taxable_monthly × 12
3. annual_tax = base_tax + excess_rate × max(annual_taxable − excess_over, 0)
4. monthly_WHT = annual_tax / 12
5. per_cutoff = monthly_WHT × 0.5
⚠️ Minimum Wage Earners (is_minimum_wage_earner = true) are fully BIR-exempt including OT/holiday — no WHT deducted.

Manila DTR Upload & Sync
/admin/payroll/manila/dtr-upload
Three ways to load attendance: CSV upload, Bayzat sync, OT approval sync. All feed the same table.
Tab 1 — CSV Upload

Upload CSV: one row per staff per working day. Required columns:

work_date staff_name actual_time_in actual_time_out regular_hours overtime_hours night_regular_hours night_overtime_hours late_minutes undertime_minutes day_type is_scheduled_rest_day absent_without_pay paid_leave_flag
ℹ️ day_type values: ordinary / rest_day / special_holiday / special_holiday_and_rest_day / regular_holiday / regular_holiday_and_rest_day
Tab 2 — Sync from OS Attendance

From Aug 2026: use this tab (Bayzat ended July 2026). Pulls punch-in/out logs from OS attendance.

  1. 1
    Select the payroll period

    The date range is pre-filled from the selected period.

  2. 2
    Click Preview Sync first

    Shows what will be synced without writing to the DB. Review all warnings before proceeding.

  3. 3
    Review sync warnings

    Two warning types may appear:

    • Unmatched Staff — OS name not found in Manila Staff Profiles. The sync still proceeds but the row is flagged. Back Office staff who clock via OS but are not on payroll appear here — this is expected, sync is not blocked for them.
    • Shift schedule not found (those rows are SKIPPED) — A payroll-eligible staff member has OS sessions but no published shift, so their day type cannot be determined. Since 2026-08-24 only their own rows are skipped — the sync still runs for everyone else. (Before that, one person's missing shift aborted the entire sync and nothing was written for anyone, which is why corrected shifts never reached the DTR.) Publish the shift or fix the name, then re-sync to include them.
    • Suspicious session (those rows are SKIPPED) — A session exceeds the plausible limit, almost certainly a forgotten clock-out. That row is skipped so the bad hours never reach payroll; everyone else still syncs. Fix the clock-out in OS Attendance, then re-sync.
    • Duplicate sessions (same staff, same day) — If a staff has two clock-in sessions for the same date, only the earliest clock-in session is kept. The duplicate is logged in the errors section.
    • Schedule conflict — published shift far from actual clock-in — The published shift starts more than 2 hours from when the person actually clocked in. The existing DTR schedule is KEPT and the row is listed for review, because applying the published shift would invent hours of false late or undertime. (In 2026-08 this protected 10 rows, including 5 days where a morning worker had an evening shift published, which would have created ~7h of phantom undertime each.) Check which side is wrong — the shift roster or the DTR.
    • Scheduled shift changes — Lists every row whose scheduled shift this sync will rewrite. Review this before clicking Sync to DTR; it is the blast radius of the operation. Genuine lateness is preserved — only schedules that agree with the clock-in are applied.
    • Not updated — already approved — The sync cannot overwrite a row whose approval_status is approved. Those rows keep their existing scheduled and clock times even though the sync reports success. Fix: un-approve the row in DTR Records (or use Edit Scheduled Shift to set the times directly), then re-run the sync. Added 2026-08-24 — before this, such rows were counted as synced and the discrepancy was invisible.
  4. 4
    Click Sync from OS Attendance

    Writes sessions to DTR. Approved rows protected. Scheduled shift times stored — enables auto-late-calculation in Edit DTR.

  5. 5
    Run DTR pre-check via Compute All

    After sync, Compute All → DTR pre-check catches overnight errors and unscheduled absences.

✅ If a corrected shift still shows old times, the sync probably never ran: any blocking warning disables Sync to DTR and nothing is written for anyone — often because of a different staff member. Clear the blockers, or fix the single row via its Schedule cell in DTR Records (type HH:MM-HH:MM).
⚠️ Closing shift (15:30–00:30): checkout may record as same day as check-in. Sync auto-corrects this. If time_out ≤ time_in still appears in DTR pre-check, use Edit DTR → set Time Out to next day.
Tab 3 — OT Approvals Sync

After OT requests are approved, sync here to update approved_ot_hours. Overrides raw computed OT from OS sync.

⚠️ Always sync OT approvals AFTER uploading DTR — syncing first has no effect (no rows to update).
Correcting Individual Records (Post-Compute)

Period Detail → DTR Correction → edit fields → click Recompute on that staff's run.

actual_time_in / actual_time_out late_minutes undertime_minutes day_type paid_leave_flag absent_without_pay approved_ot_hours

Meal Allowance & Perfect Attendance
/admin/payroll/manila/allowances
Monthly computation of two Manila-specific allowances. Run before 2H payroll computation.
Meal Allowance — ₱50/day

₱50 per working day in cutoff. DISQUALIFIED if any of:

AWOL (absent_without_pay ≥ 1 day) Shift request < 15 days advance Any shift request REJECTED Late count ≥ 3 in cutoff Total late minutes > 60 No Prior Notice flag (admin-set)
Perfect Attendance Bonus — ₱500/month

₱500 flat if zero late AND zero AWOL across BOTH cutoffs for the month.

💡 Bonus is added to the 2H run. Appears as ₱500 item when 2H is computed.

  4. 4

    Compute Payroll automatically reads stored amounts → MEAL_ALLOWANCE + PERFECT_ATTENDANCE line items.

DTR Pre-check — What Happens When You Click Compute All

Before running the engine, Compute All checks DTR integrity and shows a modal if issues are found. Prevents wrong deductions reaching payslips.

SeverityConditionAction required
ERROR undertime_minutes > 480, or time_out ≤ time_in Compute All blocked. Fix DTR (Edit DTR → set Time Out to next day) then retry.
WARNING Absent with no published shift — likely rest day Auto-fixed by Compute All. Or click "Compute Anyway (warnings only)" to proceed.
ℹ️ Pre-check only flags issues for staff with an active Manila payroll profile. Staff without a profile are skipped.
⚠️ After Edit DTR, always click Recompute on that staff's run — the engine won't auto-clear stale undertime from a previous compute.

13th Month Pay — December 2H

Accrual tracked each cutoff. Full 13th Month disbursed in December 2H run.

13th Month calculation
thirteenth_month = sum(monthly_basic_per_cutoff) / 12 × months_worked_in_year
[excludes OT, allowances, bonuses — basic pay only]
ℹ️ 13th Month Pay is tax-exempt up to ₱90,000 (TRAIN Law). WHT applied only on excess over ₱90,000.
