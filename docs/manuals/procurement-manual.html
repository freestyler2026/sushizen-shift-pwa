Generating Orders — Generate Now
  1. 1
    Select store tab

    Each store is managed separately. Select the correct store tab.

  2. 2
    Set delivery date → Generate Now

    Set order_date to the delivery date. System uses most recent Daily Inventory to calculate qty. Shows "Inventory ref: YYYY-MM-DD" after generation (or ⚠ warning if no inventory). Existing orders are skipped.

  3. 3
    Review and adjust quantities inline

    Expand each draft. Hover any qty in the Ordered column → ✏ appears. Click to open inline edit. Enter→save, Escape/✕→cancel. Editable at draft+confirmed (Manager/HQ) and approved (HQ/ADMIN only).

ℹ️ Par levels (weekday + weekend) must be set in advance. Go to the Catalog tab and click any Par cell to edit inline.
HQ Approval — Where to Find It

After Mark as Confirmed, the Approve button appears for HQ/Admin on the same Store Supplier Orders page. No separate Procurement Inbox entry.

⚠️ Confirmed orders do NOT appear in Procurement Approval Inbox or Needs Approval. Find them in Store Supplier Orders filtered by 'confirmed' status.
Supplier Emails Tab — Auto-email Setup

Managers / HQ can set a To + CC email per supplier per store. Clicking Mark as Sent on an approved order auto-sends the order via Gmail.

  1. 1
    Open the Supplier Emails tab

    Click 'Supplier Emails' at the top. Visible to Manager / HQ / ADMIN only.

  2. 2
    Click Edit next to a supplier

    Each supplier with active catalog items appears. Click Edit to open the inline form.

  3. 3
    Enter To email + CC (optional) → Save

    To = supplier's primary address. CC = comma-separated (optional). Save to apply. Next Mark as Sent auto-sends the email.

✉️ After Mark as Sent: green toast confirms email sent. ✉ icon appears on the order card. If no email configured, status becomes 'sent' with no email sent (no error).
Catalog Tab — Daily Inventory Link, Unit Price & Par Levels

The Catalog tab (Manager / HQ / ADMIN) manages active catalog items. Unit Price and Par levels are editable inline — click any cell to edit directly.

ColumnMeaning
Item Code / NameCatalog item's own code (e.g. VEG-001, SEAFOOD-002) and name
Unit PricePer-unit price (₱) shown in amber. Click cell to edit inline — Enter or click elsewhere to save. Delete value to clear. When set, PO email includes Unit Price + Total + Grand Total.
Par (wkday / wkend / default)Par levels for qty calculation. Click cell → 3 inputs open (weekday / weekend / default). ✓ to save, ✕ to cancel. System picks weekday or weekend par based on delivery date; default used if neither is set.
Daily Inv LinkThe SUP-xxx code used to look up today's stock. Green = linked, Amber = not set (full par level will be ordered).
✏️ To edit: click directly on any Unit Price or Par cell. Unit Price → type + Enter/click elsewhere to save (clear to remove). Par → 3 inputs appear → ✓ to save, ✕ to cancel.
✅ Unit prices are snapshot at generation time — the PO email shows the price active when the order was generated, not any later catalog updates.
Post-Order Flow — After Mark as Sent

All receiving and invoice matching is done directly within the Store Supplier Orders page — no separate receiving page needed.

  1. 1
    Set Delivery Date

    On a sent order, managers can click the pencil icon next to "Delivery Date" to enter the expected delivery date. An alert banner appears on this page if the date passes midnight with no receipt confirmation.

  2. 2
    Confirm Receipt

    Click Confirm Receipt on any sent order to open the receipt modal. Enter:

    • Invoice number (optional)
    • Qty received per item
    • Receipt status: Received, Partial, or Issue

    Partial → status becomes partial with remaining qty open. All items received → received.

  3. 3
    Invoice Matching (Back Office)

    On received/partial orders, an Invoice Matching section appears in the order detail. Managers enter the actual invoice price per item. The system auto-computes variance:

    VarianceDisplayAction
    < ±5%No flagNormal
    ≥ ±5%Price FlaggedHQ alert banner appears

    Once prices are reviewed, click Mark Invoice Checked to clear the alert and record who verified the invoice.

⚠ Alert Banners
BannerTrigger
Overdue DeliverySent order with delivery date in the past and no receipt
Price Variance FlaggedReceived order with ≥5% actual vs PO price, invoice not yet checked
Invoice Check PendingReceived/partial order with no invoice check for 3+ days

CK Receiving
/store/receiving
Check actual received quantities against CK's dispatched list. Flag shortages.
How to Confirm CK Receipt
  1. 1
    Open your pending CK order

    Lists orders dispatched by CK but not yet confirmed.

  2. 2
    Compare dispatched vs. received

    CK's dispatched quantities shown per item. Enter what you actually received.

  3. 3
    Flag shortages

    If received < dispatched, system auto-flags a shortage. Add a note.

  4. 4
    Confirm receipt

    Click Confirm. Admin reviews shortage flags at /admin/procurement/ck-orders.

ℹ️ After CK receipt, log cold chain data immediately while temperatures are accurate.

Vendor Delivery Confirmation Steps
  1. 1

Approval Inbox
/admin/procurement/approval-inbox
Admin's primary queue for reviewing all submitted procurement requests.
Case Lifecycle
OPEN→ CLAIMED→ IN_REVIEW→ APPROVED or REJECTED or ESCALATED
Processing a Case
  1. 1
    Review the request

    Check items, quantities, vendor, urgency, notes. Use price search for benchmarks.

  2. 2
    Claim the case

    Click Claim to self-assign. Status → CLAIMED → IN_REVIEW.

  3. 3
    Take action

    Approve → PO + vendor email. Reject → with reason. Return. Escalate. Message store.

  4. 4
    On Approve: verify PO sent

    Verify vendor email sent. Monitor vendor open/confirm in PO detail.

Escalation

Click Escalate → set target role (usually HQ) + add reason comment. Use when exceeding approval authority.

Resend Notification

Case detail → Resend Push for failed notifications. Each shows DELIVERED / FAILED + provider ref.

💡 NavBar badge shows pending count — auto-refreshes after each approve/reject/claim action.

Payments
/admin/procurement/payments
Manage payment queue — hold, release, execute. Both gates must pass first.
Payment Flow
Queued→ Held (opt.)→ Released→ Executed
Executing a Payment
  1. 1
    Verify both gates have passed

    Phase 1 (document gate) and Phase 2 (payment gate) must both pass.

  2. 2
    Check payment is not on hold

    If Held, click Release first.

  3. 3
    Execute payment

    Click Execute → payment marked executed → order moves toward CLOSED.

⚠️ Never execute payment before both gates pass. Bypassing creates audit issues and makes recovery difficult.
